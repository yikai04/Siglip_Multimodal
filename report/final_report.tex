\begin{abstract}
本项目基于 SigLIP（Sigmoid Loss for Language-Image Pretraining）模型，在 Flickr8k 数据集上实现了一个小规模图文检索系统。与 CLIP 使用 softmax 全局归一化不同，SigLIP 对每个图文对独立使用 sigmoid 判断是否匹配，对 batch size 更鲁棒。

项目经历了四个阶段的系统性优化。\textbf{第一阶段}（中期基线）：使用 ResNet18 + MLP/Transformer 从头训练，t2i\_R@1 约 27\%，发现过拟合是主要瓶颈。\textbf{第二阶段}（从头训练优化）：经过 19 组实验（Exp0--18）探索学习率调度、模型容量、数据增强等策略，最优配置（Exp6）达到 t2i\_R@1=36.65\%，但天花板明显。\textbf{第三阶段}（预训练突破）：引入预训练 ViT-B/16 替换从头训练的 ResNet18，Exp19 一跃达到 47.36\%（+10.71pp），仅 12 个 epoch 即超过 Exp6 的 100 epoch 结果。\textbf{第四阶段}（双预训练 + 部分解冻）：进一步引入预训练 DistilBERT，Exp20 全解冻导致过拟合（88M 可训练参数），Exp21 采用部分解冻策略（仅 36M 可训练参数）取得最终最优结果 t2i\_R@1=58.03\%、i2t\_R@1=60.09\%，相比基线提升 36.77 个百分点。此外，BF16 半精度推理实现 3.82$\times$ 加速且精度几乎无损，而层剪枝和 INT8 动态量化在无重训练条件下严重损害精度。
\end{abstract}

\section{引言与任务概述}
%=======================================================================

本项目是"媒体与认知"课程的大作业，要求基于 SigLIP 模型在 Flickr8k 数据集上实现图文检索系统。核心任务包括：

\begin{enumerate}[nosep]
    \item 实现 SigLIP 损失函数（sigmoid pairwise loss，区别于 CLIP 的 softmax 全局归一化）；
    \item 使用 PyTorch 实现图像编码器和文本编码器；
    \item 在 Flickr8k 数据集上训练模型，报告 Text-to-Image 与 Image-to-Text 的 Recall@K；
    \item 分析模型在多模态语义对齐方面的效果并进行可视化；
    \item 基于 \texttt{google/siglip-base-patch16-224} 预训练模型体验图文交叉相似度矩阵可视化。
\end{enumerate}

Flickr8k 数据集包含约 8000 张图像，每张配有 1--5 条英文描述，共约 40000 条图文对。数据划分为训练集（6000 张）、验证集（1000 张）和测试集（1000 张）。由于数据量较小，从头训练容易过拟合，这是本项目面临的核心挑战。

项目从最简单的基线开始（t2i\_R@1=21.26\%），经过四个阶段的系统性优化，最终达到 58.03\%（+36.77pp）。下文将按阶段详细叙述每个优化决策的动机、实施和结果。

\section{方法设计}
%=======================================================================

\subsection{SigLIP 损失函数}

SigLIP 与 CLIP 的核心区别在于损失函数。CLIP 使用 softmax 进行全局归一化（每个样本与 batch 内所有其他样本竞争），而 SigLIP 对每个图文对独立使用 sigmoid（二分类判断是否匹配），不依赖 batch size 提供足够的负样本。

设一个 batch 中包含 $|\mathcal{B}|$ 个图文样本对，图像编码为 $\mathbf{v}_i$，文本编码为 $\mathbf{t}_j$，二者归一化后的余弦相似度为：
\[
z_{ij} = \frac{\mathbf{v}_i \cdot \mathbf{t}_j}{\|\mathbf{v}_i\| \|\mathbf{t}_j\|}
\]

引入可学习温度系数 $t = \exp(\log t)$ 和偏置项 $b$，定义缩放 logits：
\[
\ell_{ij} = t \cdot z_{ij} + b
\]

匹配标签定义为对角线 $s_{ij}=+1$（正样本对），其余 $s_{ij}=-1$（负样本对）。SigLIP 的成对损失为：
\[
\mathcal{L}_{\text{pair}}(i,j) = \log\left(1 + \exp\left(-s_{ij} \cdot \ell_{ij}\right)\right) = \text{softplus}(-s_{ij} \cdot \ell_{ij})
\]

整个 batch 上的损失为：
\[
\mathcal{L}_{\text{SigLIP}} = \frac{1}{|\mathcal{B}|} \sum_{i=1}^{|\mathcal{B}|} \sum_{j=1}^{|\mathcal{B}|} \log\left(1 + \exp\left(-s_{ij}(t \cdot z_{ij} + b)\right)\right)
\]

存储 $\log(t)$ 而非直接存储 $t$，因为 $\exp()$ 的输出恒为正，无需额外约束保证 $t > 0$。实现代码：

\begin{lstlisting}[caption={SigLIP 损失函数 forward}]
def forward(self, image_embeds, text_embeds):
    image_embeds = F.normalize(image_embeds, dim=-1)
    text_embeds  = F.normalize(text_embeds, dim=-1)
    logits = image_embeds @ text_embeds.T
    t = self.logit_scale.exp()                   # 可学习温度
    b = self.logit_bias                          # 可学习偏置
    logits = t * logits + b
    B = logits.size(0)
    labels = 2 * torch.eye(B, device=logits.device) - 1  # +1/-1
    loss = -labels * logits
    loss = F.softplus(loss)
    return loss.sum() / B
\end{lstlisting}

\subsection{Baseline 架构：ResNet18 + Transformer}

\subsubsection{图像编码器：ResNet18}

采用自定义 ResNet18 作为图像编码器，核心组件为 \texttt{BasicBlock}：

\begin{lstlisting}[caption={ResNet BasicBlock 实现}]
def __init__(self, in_channels, out_channels, stride=1, downsample=None):
    super().__init__()
    self.conv1 = nn.Conv2d(in_channels, out_channels,
                      kernel_size=3, stride=stride, padding=1, bias=False)
    self.bn1   = nn.BatchNorm2d(out_channels)
    self.conv2 = nn.Conv2d(out_channels, out_channels,
                    kernel_size=3, stride=1, padding=1, bias=False)
    self.bn2   = nn.BatchNorm2d(out_channels)
    self.relu  = nn.ReLU(inplace=True)
    self.downsample = downsample
\end{lstlisting}

残差连接：$\text{out} = \text{ReLU}(\text{BN}_2(\text{Conv}_2(\text{ReLU}(\text{BN}_1(\text{Conv}_1(x))))) + \text{identity})$。当主路改变了通道数或空间尺寸时，\texttt{downsample}（1$\times$1 卷积+BN）对齐捷径形状。

最终架构：4 层残差层（通道数 $[w, 2w, 4w, 8w]$，$w$ 为 base width），全局平均池化后接线性投影层映射到共享语义空间（维度 256）。最优配置使用 $w=48$。

\subsubsection{文本编码器：Transformer}

采用 2 层 Pre-LN Transformer 作为文本编码器：

\begin{lstlisting}[caption={Transformer 文本编码器 forward}]
def forward(self, input_ids):
    x = self.token_embedding(input_ids)          # [B, L, D]
    x = self.positional_encoding(x)               # 加位置编码
    padding_mask = input_ids.eq(self.padding_idx)  # True=忽略
    x = self.encoder(x, src_key_padding_mask=padding_mask)
    mask = (~padding_mask).unsqueeze(-1).float()
    x = (x * mask).sum(dim=1) / mask.sum(dim=1).clamp(min=1)  # 均值池化
    x = self.proj(x)                               # 线性投影
    return x
\end{lstlisting}

关键设计：均值池化时忽略 PAD 位置，仅对有效 token 做加权平均；4 头注意力（$D=256$，每头 64 维），FFN 隐藏维度 1024。

\subsection{预训练架构演进}

Baseline 架构在 Flickr8k 小数据集上从头训练的天花板约为 36.65\%（Exp6）。为了突破这一瓶颈，我们逐步引入预训练模型，经历了三次架构演进：

\noindent \textbf{Exp19}：将图像编码器替换为 HuggingFace 预训练的 \texttt{google/siglip-base-patch16-224} 的 ViT-B/16（86M 参数，全部冻结），仅训练 2 层 Transformer 文本编码器（$d=768$，12 头注意力）和 image adapter（线性层将 ViT 输出映射到共享空间）。图像预处理改用 SigLIP 归一化（mean=[0.5, 0.5, 0.5]，std=[0.5, 0.5, 0.5]）匹配预训练分布。\\

\noindent \textbf{Exp20}：进一步将文本编码器替换为预训练 DistilBERT-base-uncased（6 层，66M 参数），ViT 解冻顶层 3 层，DistilBERT 全部 6 层解冻。总可训练参数 88M，在 Flickr8k 仅 30K 训练对的情况下严重过拟合。\\

\noindent \textbf{Exp21（最优模型）}：采用部分解冻策略——ViT 仅解冻顶层 3 层（21M 参数），DistilBERT 仅解冻顶层 2 层（14M 参数），底层保持冻结保护预训练知识。配合差分学习率：ViT 顶层 LR=$1\times 10^{-5}$，DistilBERT 顶层 LR=$2\times 10^{-5}$，投影层 LR=$3\times 10^{-4}$。可训练参数从 88M 降至 36M，训练健康无过拟合。

\subsection{检索评估方法}

实现分组检索评估，计算 Text-to-Image 和 Image-to-Text 的 Recall@K：

\begin{itemize}[nosep]
    \item 同一图像有多个 caption，对同一 image\_id 的多个图像 embedding 取均值后重新归一化；
    \item t2i 检索：对每条文本，排序所有 unique 图像，检查正确图像是否在 Top-K 中；
    \item i2t 检索：对每张图像，排序所有文本，检查 Top-K 中是否包含任意一条正确 caption。
\end{itemize}

\section{实验与结果}
%=======================================================================

本节按项目进展的四个阶段叙述每个优化决策的动机、实施和结果分析。

\subsection{Phase I：中期基线}

项目中期阶段，使用 ResNet18 ($w=32$) 作为图像编码器，分别搭配 MLP 和 Transformer 两种文本编码器，以常数学习率 $3\times 10^{-4}$ 训练。训练配置如下：

\noindent \textbf{MLP vs Transformer 分析}：出乎意料的是，MLP 文本编码器的检索指标与 Transformer 基本持平，在 R@5/R@10 上甚至更优。这一现象在当前设定下是合理的：

\begin{enumerate}[nosep]
    \item \textbf{数据量不足}：Flickr8k 仅约 6000 对训练图文，Transformer 参数量远大于 MLP，更容易记忆训练样本而非学习泛化特征（MLP test\_loss=2.94 vs Transformer 3.91）；
    \item \textbf{短文本场景}：Flickr8k caption 平均仅约 10 词，多为简单描述（如 ``a dog is running on grass''），均值池化已能捕捉关键词信息，Transformer 的上下文建模优势无法充分体现；
    \item \textbf{对比学习依赖关键词匹配}：在小规模对比学习框架下，模型最有效的策略是将视觉概念与关键词对齐，MLP 的均值池化天然适合这种模式。
\end{enumerate}

\noindent 中期阶段的核心发现是\textbf{过拟合}——Transformer 训练 200 epoch 后 train\_loss 远低于 test\_loss，常数学习率无法在后期减小参数更新幅度。后续优化以此为出发点。

\subsection{Phase II：从头训练优化（Exp0--18)}

从中期基线出发，我们系统性地探索了 19 组实验，按优化主题分组分析如下。所有实验使用相同的 ResNet18 + Transformer baseline 架构，仅在训练策略上做变化。

\subsubsection{学习率调度——最关键改进}

Exp0 使用常数学习率 $3\times 10^{-4}$ 训练 30 epoch，t2i\_R@1=21.26\%，这是整个项目的最低基线。Exp1 仅将常数学习率替换为 Cosine Warmup Scheduler（warmup 10\%，最小 LR 比率 0.01），t2i\_R@1 跃升至 29.83\%，提升 \textbf{8.57 个百分点}——这是从头训练阶段最关键的单步改进。

Cosine Warmup 有效的原因：warmup 阶段让模型从随机初始化平稳过渡，避免初始梯度过大导致训练崩溃；cosine 衰减让后期参数更新幅度逐渐减小，缓解过拟合。Exp9 进一步测试了更高学习率（$5\times 10^{-4}$），反而降至 34.55\%，说明 Flickr8k 小数据集上默认 LR 已接近最优。

\subsubsection{模型容量——wider ResNet 有效，但过宽过拟合}

Exp4 将 ResNet 宽度从 $w=32$ 提升至 $w=48$ 并配合 cosine warmup 训练 100 epoch，t2i\_R@1=34.78\%。Exp5 加入 mild ColorJitter（strength=0.2）后达到 35.86\%。Exp6 在此基础上训练 100 epoch，达到从头训练最优 \textbf{36.65\%}。

然而，继续增大容量反而损害性能：Exp17 使用 $w=64$ 仅得 32.53\%（不如 $w=48$）；Exp7 尝试更大 Transformer（4 层 + 8 头 + $d=512$），因训练过慢且效果极差被提前终止（$\sim$15\% R@1）；Exp10 使用 MLP 投影头仅得 29.63\%，额外参数加剧了过拟合。结论：\textbf{$w=48$ 是模型容量与泛化的最佳平衡点}。

\subsubsection{数据增强——Flickr8k 对增强极度敏感}

Flickr8k 图像已较小（约 $500\times 400$），进一步裁剪或扰动容易丢失语义关键区域：

\begin{itemize}[nosep]
    \item \textbf{RandomResizedCrop}：scale=(0.5,1.0)（Exp2）降至 12.58\%，裁剪过小丢失关键视觉信息；scale=(0.75,1.0)（Exp3）降至 27.01\%，仍不如简单 Resize；
    \item \textbf{ColorJitter}：mild CJ（strength=0.2，Exp5）轻微有益；strong CJ（strength=0.3，Exp16）降至 30.92\%，过强颜色扰动损害性能；
    \item \textbf{RandAugment}（Exp13）和 \textbf{TrivialAugment}（Exp14）：分别降至 24.69\% 和 21.82\%，这些为大规模数据集设计的策略在 Flickr8k 上过于激进。
\end{itemize}

\subsubsection{正则与训练策略——多数无效}

\begin{itemize}[nosep]
    \item \textbf{更长训练}（Exp8，200 epoch）：约 30\%，训练至 97 epoch 时已明显过拟合；
    \item \textbf{更强 weight\_decay}（Exp11，wd=0.05）：34.11\%，略逊于默认；
    \item \textbf{EMA}（Exp6、Exp12）：无论 decay=0.999 还是 0.99，EMA 模型测试 R@1 均仅为 0.07\%，原因不明但一致出现；
    \item \textbf{梯度累积}（Exp15，effective batch=128）：29.56\%，LR scheduler 步数减少反而更差。
\end{itemize}

\subsubsection{可重复性}

Exp18 使用与 Exp6 相同的配置独立复现，t2i\_R@1=32.23\%，与原 Exp6 的 36.65\% 相差 4.42\%。这说明 Flickr8k 测试集评估存在约 4--5\% 的随机方差，源于训练随机性在小数据集上的放大效应。

\textbf{Phase II 总结}：从头训练的最优配置为 Exp6（Cosine Warmup + $w=48$ + mild CJ），t2i\_R@1=36.65\%。19 组实验的系统性探索揭示了一个关键瓶颈——在小数据集上从头训练的 ResNet18 无法提供足够高质量的视觉特征，无论怎样调整训练策略，天花板都在 36--37\% 左右。这促使我们转向预训练模型。

\subsection{Phase III：预训练视觉编码器突破（Exp19)}

Exp0--18 均使用从头训练的 ResNet18 作为图像编码器。在 Flickr8k 仅 6000 张训练图的小数据场景下，ResNet18 无法学到高质量的视觉特征表示——这是从头训练天花板 36.65\% 的根本原因。

Exp19 将图像编码器替换为 \texttt{google/siglip-base-patch16-224} 的预训练 ViT-B/16（86M 参数），全部冻结以保护在海量数据上学到的视觉特征。仅训练 2 层 Transformer 文本编码器（$d=768$，18.7M 可训练参数）和 image adapter。

结果：t2i\_R@1 从 36.65\% 跃升至 \textbf{47.36\%}，提升 \textbf{10.71 个百分点}——这是所有实验中最大的单步改进。仅 12 个 epoch 即超过 Exp6 的 100 epoch 结果，充分验证了预训练视觉特征的价值：文本编码器不再需要从头学习视觉特征提取，只需学习如何将文本语义对齐到已有的高质量视觉嵌入空间。

\subsection{Phase IV：双预训练与部分解冻（Exp20/21)}

Exp19 证明了预训练视觉编码器的价值，但文本编码器仍从头训练（2 层 Transformer，词表仅覆盖 Flickr8k 的 $\sim$5000 词），限制了图文对齐的精度。Exp20 和 Exp21 进一步引入预训练 DistilBERT-base-uncased（30522 词表，6 层 Transformer）作为文本编码器。

\textbf{Exp20 的过拟合问题}：DistilBERT 全部 6 层解冻（66M 可训练参数），加上 ViT 顶层 3 层解冻（6M）和投影层（12M），总可训练参数达 88M。在 Flickr8k 仅 30K 训练对的情况下严重过拟合——train\_loss 从 epoch 25 后持续下降至 0.1x，但 val\_loss 停滞在 0.94--0.96 不再下降。虽然测试 t2i\_R@1 达到 58.48\%，但训练过程不健康。

\textbf{Exp21 的部分解冻策略}：借鉴 ViT 的经验，DistilBERT 也只解冻顶层 2 层（第 5、6 层，14M 可训练参数），底层 4 层 + embeddings 保持冻结。配合差分学习率：ViT 顶层 LR=$1\times 10^{-5}$（最小，保护预训练知识），DistilBERT 顶层 LR=$2\times 10^{-5}$（中等），投影层 LR=$3\times 10^{-4}$（最大，需要从头学习）。可训练参数从 88M 降至 36M（减少 60\%）。

\subsection{模型偏好与局限性总结}

\begin{enumerate}
    \item \textbf{偏好具象、单实体描述}：关键词与图像视觉特征容易对齐，检索效果较好。
    \item \textbf{对抽象/模糊描述薄弱}：缺乏具体语义的文本几乎无法检索到正确图像。
    \item \textbf{多实体组合和隐含语义是难点}：涉及空间关系或需要推理的描述对当前模型构成挑战。
    \item \textbf{同类语义图像难以区分实例}：Recall@K 精确匹配指标可能低估模型的实际语义理解能力。
    \item \textbf{预训练特征显著提升嵌入质量}：Exp19 相似度高于从头训练模型，但仍低于完全预训练模型，说明视觉和文本编码器都需进一步提升。
\end{enumerate}

\section{推理优化实验}
%=======================================================================

最优模型（Exp21）总参数 159.8M，推理时需遍历 12 层 ViT + 6 层 DistilBERT。本节探索三种推理优化策略，评估精度与速度的权衡。

\subsection{实验方法}

\begin{enumerate}[nosep]
    \item \textbf{半精度推理（FP16/BF16）}：将模型权重从 FP32 转为 16 位浮点，利用 RTX 4090 Tensor Core 加速。$\exp(t)$ 计算保持 FP32 防止数值溢出。
    \item \textbf{层剪枝}：直接删除 ViT/DistilBERT 的底层冻结层，减少前向传播步数。
    \item \textbf{INT8 动态量化}：使用 PyTorch \texttt{quantize\_dynamic} 将 \texttt{nn.Linear} 权重转为 INT8（仅支持 CPU）。
\end{enumerate}

\end{table}

\subsection{结果分析}

\textbf{BF16 是最优部署方案}：在 RTX 4090（Ada Lovelace 架构）上 BF16 有原生硬件支持，精度范围优于 FP16。实现 3.82$\times$ 加速（7.68→2.01 ms/sample）、50\% 模型体积缩减（610→305 MB）、精度几乎无损（t2i\_R@1 仅下降 0.02pp）。

\textbf{层剪枝不可行}：预训练 ViT 的 12 层 encoder 形成顺序处理流水线，删除底层导致后续层接收到未经预期的原始 embedding，产生灾难性精度崩溃（R@1 $\sim$0\%）。结构化剪枝必须伴随重训练或知识蒸馏。

\textbf{INT8 动态量化精度灾难}：冻结层量化后 t2i\_R@1 从 58.03\% 降至 42.91\%（-15.12pp），全量化更降至 36.48\%。且 \texttt{quantize\_dynamic} 的 INT8 Linear 仅在 CPU 上有效，GPU 上反而更慢。

\section{结论与展望}
%=======================================================================

\subsection{主要结论}

\begin{enumerate}[nosep]
    \item \textbf{从头训练阶段}：Cosine Warmup 是最关键优化（+8.57pp）；$w=48$ + mild CJ 是容量与泛化的最佳平衡；Flickr8k 对增强极度敏感（RRC/RandAugment/TrivialAugment 均严重损害）；更大容量反而过拟合；从头训练天花板 $\sim$36.65\%。
    \item \textbf{预训练突破}：预训练视觉编码器是突破天花板的关键——Exp19 冻结 ViT-B/16 后 t2i\_R@1 从 36.65\% 跃升至 47.36\%（+10.71pp）。
    \item \textbf{部分解冻优于全解冻}：Exp20 全解冻 DistilBERT（88M 可训练）导致过拟合；Exp21 只解冻顶层（36M 可训练）后训练更健康，综合指标更优。
    \item \textbf{差分学习率}：ViT 顶层 LR=$1\times 10^{-5}$，DistilBERT 顶层 LR=$2\times 10^{-5}$，投影层 LR=$3\times 10^{-4}$——不同层以不同速率适应，保护底层预训练知识。
    \item \textbf{BF16 是最实用推理优化}：3.82$\times$ 加速、50\% 体积缩减、精度损失 <0.02pp。
    \item \textbf{层剪枝/INT8 在无重训练下不可行}：预训练 Transformer 层间依赖强，直接删除底层或量化冻结层导致灾难性精度崩溃。
\end{enumerate}

\subsection{改进方向}

\begin{enumerate}
    \item \textbf{渐进式解冻}：Exp21 已部分解冻顶层，可进一步尝试逐层递增解冻数量，平衡精度与过拟合。

    \item \textbf{更大规模数据集}：迁移到 Flickr30k（30000 张）或 COCO（120000 张），对比学习需要更多负样本对，也可尝试全解冻 DistilBERT。

    \item \textbf{知识蒸馏 + 层剪枝}：层剪枝在无重训练下不可行，但若结合知识蒸馏（用完整模型指导剪枝后模型重训练），可能实现推理加速且保持精度。

    \item \textbf{Hard Negative Mining}：主动挖掘模型容易混淆的负样本对（如同类语义图像），提供更有针对性的训练信号，提升实例级区分能力。

    \item \textbf{GPU 专用量化}：尝试 BitsAndBytes INT8 量化（HuggingFace 推荐方案）或 torch.compile()，可能提供超越 BF16 的进一步加速。
\end{enumerate}

\subsection*{A.1 SigLIP 损失函数}

\begin{lstlisting}[language=Python]
class SigLIPLoss(nn.Module):
    def __init__(self, init_logit_scale=10.0, init_logit_bias=-10.0):
        super().__init__()
        self.logit_scale = nn.Parameter(torch.log(torch.tensor(init_logit_scale)))
        self.logit_bias = nn.Parameter(torch.tensor(init_logit_bias))

    def forward(self, image_embeds, text_embeds):
        image_embeds = F.normalize(image_embeds, dim=-1)
        text_embeds  = F.normalize(text_embeds, dim=-1)
        logits = image_embeds @ text_embeds.T
        t = self.logit_scale.exp()
        b = self.logit_bias
        logits = t * logits + b
        B = logits.size(0)
        labels = 2 * torch.eye(B, device=logits.device) - 1
        loss = -labels * logits
        loss = F.softplus(loss)
        return loss.sum() / B
\end{lstlisting}
