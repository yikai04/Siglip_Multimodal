\begin{abstract}
本项目基于 SigLIP（Sigmoid Loss for Language-Image Pretraining）模型，在 Flickr8k 数据集上实现了一个小规模图文检索系统。与 CLIP 使用 softmax 进行全局归一化不同，SigLIP 对每个图文对独立使用 sigmoid 判断是否匹配，对 batch size 更鲁棒。本文详细介绍了模型实现、训练优化过程、实验结果分析及可视化。经过 19 组实验的系统性探索，从头训练 ResNet18 的天花板约为 t2i\_R@1=36.65\%（Exp6）。随后转向预训练模型：Exp19 仅引入预训练视觉编码器提升至 47.36\%；Exp20/21 进一步引入预训练 DistilBERT 文本编码器并采用部分解冻策略，最终最优模型（Exp21）取得 t2i\_R@1=58.03\%、i2t\_R@1=60.09\%，相比 Exp6 提升 21.38 个百分点。此外，本文对最优模型进行了推理优化实验：BF16 半精度推理实现 3.8$\times$ 加速且精度几乎无损，模型体积缩小 50\%；而层剪枝和 INT8 动态量化在无重训练条件下严重损害精度。
\end{abstract}

\section{任务概述}
%=======================================================================

本项目基于 SigLIP 模型，在 Flickr8k 数据集上训练并评估一个图文检索系统。核心任务包括：

\begin{enumerate}[nosep]
    \item 理解 CLIP 与 SigLIP 在损失函数上的差异；
    \item 使用 PyTorch 实现图像编码器（ResNet18）、文本编码器（Transformer）和 SigLIP 损失函数；
    \item 在 Flickr8k 数据集上训练模型，报告 Text-to-Image 与 Image-to-Text 的 Recall@1/5/10；
    \item 分析模型在多模态语义对齐方面的效果并进行可视化；
    \item 基于 \texttt{google/siglip-base-patch16-224} 预训练模型体验图文交叉相似度矩阵可视化。
\end{enumerate}

Flickr8k 数据集包含 8000 张图像，每张配有 1--5 条英文描述，共约 40000 条图文对。数据划分为训练集（6000 张）、验证集（1000 张）和测试集（1000 张）。

\section{模型结构}

\subsection{图像编码器：ResNet18}

采用自定义 ResNet18 作为图像编码器，核心组件为 \texttt{BasicBlock}：

\begin{lstlisting}[caption={ResNet BasicBlock 实现}]
def __init__(self, in_channels, out_channels, stride=1, downsample=None):
    super().__init__()
    self.conv1 = nn.Conv2d(in_channels, out_channels,
                      kernel_size=3, stride=stride, padding=1, bias=False)
    self.bn1   = nn.BatchNorm2d(out_channels)
    self.conv2 = nn.Conv2d(out_channels, out_channels,
                    kernel_size=3, stride=1, padding=1, bias=False)
    self.bn2   = nn.BatchNorm2d(out_channels)
    self.relu  = nn.ReLU(inplace=True)
    self.downsample = downsample
\end{lstlisting}

残差连接逻辑为：
\[
\text{out} = \text{ReLU}(\text{BN}_2(\text{Conv}_2(\text{ReLU}(\text{BN}_1(\text{Conv}_1(x))))) + \text{identity})
\]

当主路改变了通道数或空间尺寸时，\texttt{downsample}（1$\times$1 卷积+BN）对齐捷径形状。

最终架构：4 层残差层（通道数 $[w, 2w, 4w, 8w]$，$w$ 为 base width），全局平均池化后接线性投影层映射到共享语义空间（维度 256）。最优配置使用 $w=48$。

\subsection{文本编码器：Transformer}

采用 2 层 Pre-LN Transformer 作为文本编码器：

\begin{lstlisting}[caption={Transformer 文本编码器 forward}]
def forward(self, input_ids):
    x = self.token_embedding(input_ids)          # [B, L, D]
    x = self.positional_encoding(x)               # 加位置编码
    padding_mask = input_ids.eq(self.padding_idx)  # True=忽略
    x = self.encoder(x, src_key_padding_mask=padding_mask)
    mask = (~padding_mask).unsqueeze(-1).float()
    x = (x * mask).sum(dim=1) / mask.sum(dim=1).clamp(min=1)  # 均值池化
    x = self.proj(x)                               # 线性投影
    return x
\end{lstlisting}

关键设计：均值池化时忽略 PAD 位置，仅对有效 token 做加权平均；4 头注意力（$D=256$，每头 64 维），FFN 隐藏维度 1024。

\subsection{SigLIP 损失函数}

SigLIP 与 CLIP 的核心区别在于损失函数：CLIP 使用 softmax 进行全局归一化（每个样本与 batch 内所有其他样本竞争），而 SigLIP 对每个图文对独立使用 sigmoid（二分类判断是否匹配）。

设一个 batch 中包含 $|\mathcal{B}|$ 个图文样本对，图像编码为 $\mathbf{v}_i$，文本编码为 $\mathbf{t}_j$，二者归一化后的余弦相似度为：
\[
z_{ij} = \frac{\mathbf{v}_i \cdot \mathbf{t}_j}{\|\mathbf{v}_i\| \|\mathbf{t}_j\|}
\]

引入可学习温度系数 $t = \exp(\log t)$ 和偏置项 $b$，定义缩放 logits：
\[
\ell_{ij} = t \cdot z_{ij} + b
\]

匹配标签定义为对角线 $s_{ij}=+1$（正样本对），其余 $s_{ij}=-1$（负样本对）。SigLIP 的成对损失为：
\[
\mathcal{L}_{\text{pair}}(i,j) = \log\left(1 + \exp\left(-s_{ij} \cdot \ell_{ij}\right)\right) = \text{softplus}(-s_{ij} \cdot \ell_{ij})
\]

整个 batch 上的损失为：
\[
\mathcal{L}_{\text{SigLIP}} = \frac{1}{|\mathcal{B}|} \sum_{i=1}^{|\mathcal{B}|} \sum_{j=1}^{|\mathcal{B}|} \log\left(1 + \exp\left(-s_{ij}(t \cdot z_{ij} + b)\right)\right)
\]

实现代码：

\begin{lstlisting}[caption={SigLIP 损失函数实现}]
def forward(self, image_embeds, text_embeds):
    image_embeds = F.normalize(image_embeds, dim=-1)
    text_embeds  = F.normalize(text_embeds, dim=-1)
    logits = image_embeds @ text_embeds.T        # 余弦相似度矩阵
    t = self.logit_scale.exp()                   # 可学习温度
    b = self.logit_bias                          # 可学习偏置
    logits = t * logits + b                      # 缩放 + 偏置
    B = logits.size(0)
    labels = 2 * torch.eye(B, device=logits.device) - 1  # +1/-1
    loss = -labels * logits
    loss = F.softplus(loss)                      # log(1 + exp(s*(-t*z+b)))
    return loss.sum() / B
\end{lstlisting}

\subsection{检索评估函数}

实现分组检索评估，计算 Text-to-Image 和 Image-to-Text 的 Recall@K：

\begin{itemize}[nosep]
    \item 同一图像有多个 caption，对同一 image\_id 的多个图像 embedding 取均值后重新归一化；
    \item t2i 检索：对每条文本，排序所有 unique 图像，检查正确图像是否在 Top-K 中；
    \item i2t 检索：对每张图像，排序所有文本，检查 Top-K 中是否包含任意一条正确 caption。
\end{itemize}

\subsection{关键优化分析}

\subsubsection{学习率调度（最关键改进）}

从 Exp0 到 Exp1，仅将常数学习率替换为 Cosine Warmup Scheduler（warmup 10\%，最小 LR 比率 0.01），t2i\_R@1 从 21.26\% 跃升至 29.83\%，提升 8.57 个百分点。这是因为：

\begin{itemize}[nosep]
    \item Warmup 阶段让模型从随机初始化平稳过渡，避免初始阶段梯度过大导致训练崩溃；
    \item Cosine 衰减让后期参数更新幅度逐渐减小，缓解过拟合；
    \item 最小 LR 比率 0.01 保证训练末期仍有微量学习，而非完全停滞。
\end{itemize}

\subsubsection{图像编码器宽度提升}

Exp4（width=32, cosine, 100ep）因服务器故障未能完成。Exp5 将 ResNet 宽度从 32 提升至 48 并加入 mild ColorJitter（strength=0.2），t2i\_R@1 达到 35.86\%。更宽的 ResNet 提供了更丰富的视觉特征表示能力，在 Flickr8k 这种小数据集上，width=48 是模型容量与泛化能力的最佳平衡点。

\subsubsection{ColorJitter 的双重效应}

\begin{itemize}[nosep]
    \item Mild ColorJitter（strength=0.2）：轻微有益，Exp5 比 Exp4 提升约 1\%；
    \item Strong ColorJitter（strength=0.3，Exp16）：反而损害性能（30.92\%），说明 Flickr8k 数据量不足以支撑强颜色扰动。
\end{itemize}

\subsubsection{自动增强策略的失败}

RandAugment（Exp13，t2i\_R@1=24.69\%）和 TrivialAugmentWide（Exp14，21.82\%）均严重损害性能。这些策略设计用于大规模数据集（如 ImageNet），在 Flickr8k 的小数据场景下过于激进，破坏了图像的语义信息。

\subsubsection{数据裁剪策略}

RandomResizedCrop 在 Flickr8k 上表现不佳：
\begin{itemize}[nosep]
    \item scale=(0.5, 1.0)（Exp2）：t2i\_R@1=12.58\%，严重损害——裁剪过小导致关键视觉信息丢失；
    \item scale=(0.75, 1.0)（Exp3）：t2i\_R@1=27.01\%，比 Resize 更差——裁剪仍会损失边缘信息。
\end{itemize}

结论：Flickr8k 图像已较小（约 500$\times$400），进一步裁剪容易丢失语义关键区域。

\subsubsection{模型容量与过拟合}

\begin{itemize}[nosep]
    \item 更大 Transformer（4L+8H+d512，Exp7）：因训练过慢被终止，更大模型在 Flickr8k 上过拟合风险极高；
    \item 更宽 ResNet（width=64，Exp17）：t2i\_R@1=32.53\%，不如 width=48——模型容量过大导致过拟合；
    \item MLP 投影头（Exp10）：t2i\_R@1=29.63\%，额外参数加剧了小数据集上的过拟合。
\end{itemize}

\subsubsection{其他策略的失败}

\begin{itemize}[nosep]
    \item EMA（Exp6、Exp12）：无论 decay=0.999 还是 0.99，无论立即还是延迟启动，EMA 模型的测试 R@1 均为 0.07\%，原因不明但一致出现；
    \item 梯度累积（Exp15）：有效 batch 从 64 增至 128，但由于 LR scheduler 步数减少，效果反而更差（29.56\%）；
    \item 更强 weight\_decay（Exp11，wd=0.05）：34.11\%，略逊于默认 wd=1e-4。
\end{itemize}

\subsubsection{训练集方差}

Exp18 使用与 Exp6 相同的配置独立复现，t2i\_R@1=32.23\%，与原 Exp6 的 36.65\% 相差 4.42\%，说明 Flickr8k 测试集评估存在约 4--5\% 的随机方差，这源于训练随机性（数据 shuffle、初始化）在小数据集上的放大效应。

\subsubsection{预训练视觉编码器（突破性改进）}

Exp0--18 均使用从头训练的 ResNet18 作为图像编码器，在 Flickr8k 的小数据场景下，视觉特征质量成为瓶颈。Exp19 将图像编码器替换为 HuggingFace 预训练的 \texttt{google/siglip-base-patch16-224} 的 ViT-B/16（冻结），仅训练文本编码器和 SigLIP loss 参数。

\begin{itemize}[nosep]
    \item 冻结 ViT-B/16（86M 参数）提供高质量视觉特征，无需在 Flickr8k 上从头学习；
    \item 可训练参数仅 18.7M（2 层 Transformer 文本编码器 + image adapter），避免过拟合；
    \item 图像预处理改用 SigLIP 归一化（mean=[0.5,0.5,0.5], std=[0.5,0.5,0.5]）匹配预训练分布；
    \item embed\_dim=768 匹配 ViT 输出维度，文本编码器同步使用 768 维、12 头注意力。
\end{itemize}

结果：t2i\_R@1 从 36.65\% 跃升至 47.36\%，提升 10.71 个百分点，是所有实验中最大的单步改进。仅 12 个 epoch 即超过 Exp6 的 100 epoch 结果，充分验证了预训练视觉特征的价值。

\subsubsection{双预训练模型与部分解冻策略（Exp20/21）}

Exp19 证明了预训练视觉编码器的价值，但文本编码器仍从头训练，限制了图文对齐的精度。Exp20 和 Exp21 进一步引入预训练 DistilBERT-base-uncased 作为文本编码器：

\begin{table}[H]
\centering
\caption{预训练模型实验对比}
\begin{tabular}{lcccc}
\toprule
\textbf{实验} & \textbf{视觉编码器} & \textbf{文本编码器} & \textbf{解冻策略} & \textbf{可训练参数} \\
\midrule
Exp19 & 冻结 ViT-B/16 & 从头训练 Transformer & ViT 全冻结 & 18.7M \\
Exp20 & ViT-B/16 顶层3层 & DistilBERT 全6层 & DistilBERT 全解冻 & 88.2M \\

\textbf{Exp20 的过拟合问题}：DistilBERT 全部 6 层解冻（66M 可训练参数），在 Flickr8k 仅 30K 训练对的情况下严重过拟合——train\_loss 从 epoch 25 后持续下降，但 val\_loss 停滞在 0.94--0.96 并不再下降。

\textbf{Exp21 的部分解冻策略}：借鉴 ViT 的经验，DistilBERT 也只解冻顶层 2 层（第5、6层），底层 4 层 + embeddings 保持冻结。可训练参数从 88M 降至 36M，减少 60\%。结果：test t2i\_R@1=58.03\%，虽然比 Exp20 的 58.48\% 低 0.45pp，但 i2t\_R@1 更高（60.09\% vs 59.67\%），test\_loss 更低（0.9233 vs 0.9669），训练全程无过拟合。

\subsection{训练过程分析}

\textbf{Exp6（从头训练 ResNet18）}的训练曲线：

\begin{itemize}[nosep]
    \item \textbf{快速上升期}（epoch 1--20）：t2i\_R@1 从 0\% 快速升至 12\%，模型学习基本图文对齐能力；
    \item \textbf{稳步增长期}（epoch 20--60）：R@1 缓慢提升至 30\%，Cosine 衰减让模型更精细地优化嵌入空间；
    \item \textbf{收敛平台期}（epoch 60--100）：R@1 在 33--35\% 波动，模型接近收敛，val\_loss 稳定在 3.5 左右；
    \item \textbf{过拟合信号}：train\_loss 从初期 7.0 降至末期 0.22，val\_loss 从 5.8 降至 3.5 后稳定，train/val loss 差距约 3.3。
\end{itemize}

\textbf{Exp19（冻结预训练 ViT）}的训练曲线：

\begin{itemize}[nosep]
    \item \textbf{极速上升期}（epoch 1--12）：t2i\_R@1 从 0\% 快速升至 38.64\%，仅 12 个 epoch 即超过 Exp6 的 100 epoch 结果——预训练 ViT 的高质量视觉特征让文本编码器只需学习对齐而非从头提取特征；
    \item \textbf{稳步提升期}（epoch 12--40）：R@1 缓慢提升至 43\%，val\_loss 从 1.6 降至 1.5；
    \item \textbf{收敛期}（epoch 40--70）：R@1 稳定在 44--46\%，val\_loss 回升至 2.0+，train\_loss 降至 0.1x，过拟合明显但由于只有文本编码器可训练，过拟合速度较慢；
    \item \textbf{可学习参数}：$t$ 从 10.0 增长至 62.59，$b$ 从 -10.0 微调至 -10.57，温度系数远大于 Exp6 的 31.06，说明预训练视觉特征配合更大的温度系数能更好地区分正负样本。
\end{itemize}

\subsection{模型偏好与局限性总结}

综合以上可视化分析，模型表现出以下偏好和局限：

\begin{enumerate}
    \item \textbf{偏好具象、单实体描述}：模型对描述单一明确对象（如 ``a dog running on grass''）的文本检索效果较好，这类描述的关键词与图像视觉特征容易对齐。

    \item \textbf{对抽象/模糊描述薄弱}：缺乏具体语义的文本（如 ``I have no idea''）几乎无法检索到正确图像，从头训练和 Exp19 模型均存在此问题。

    \item \textbf{多实体组合和隐含语义是难点}：Exp19 的 Bad Case 表明，涉及多实体空间关系（``A boy rides a skateboard with a bike to his right''）或需要推理的反问句（``Where is the rest of his racket?''）对当前模型仍构成挑战。

    \item \textbf{同类语义图像难以区分实例}：当数据集中存在多张语义高度相似的图像时，Recall@K 这种精确匹配指标可能低估模型的实际语义理解能力。从语义角度检索正确但非精确匹配仍被判为失败。

    \item \textbf{预训练视觉特征显著提升嵌入质量}：Exp19 的相似度分数（0.28--0.35）高于从头训练模型（0.15--0.28），但仍低于完全预训练模型（0.35--0.45），说明视觉特征质量是关键瓶颈，但文本编码器也需进一步提升。
\end{enumerate}

\section{推理速度优化实验}
%=======================================================================

最优模型（Exp21）总参数 159.8M，推理时需遍历 12 层 ViT + 6 层 DistilBERT。本节探索三种推理优化策略，评估精度与速度的权衡。

\subsection{实验方法}

\begin{enumerate}[nosep]
    \item \textbf{半精度推理（FP16/BF16）}：将模型权重从 FP32 转换为 16 位浮点，利用 RTX 4090 的 Tensor Core 加速。SigLIPLoss 的 $\exp(t)$ 计算保持 FP32 以防止数值溢出。
    \item \textbf{层剪枝}：直接删除 ViT/DistilBERT 的底层冻结层，减少 Transformer 前向传播步数。
    \item \textbf{INT8 动态量化}：使用 PyTorch \texttt{quantize\_dynamic} 将 \texttt{nn.Linear} 层权重转为 INT8（仅支持 CPU 推理）。
\end{enumerate}

\subsection{实验结果}

\begin{table}[H]
\centering
\caption{推理优化实验结果对比}
\begin{tabular}{lcccccc}
\toprule
\textbf{方法} & \textbf{t2i\_R@1} & \textbf{i2t\_R@1} & \textbf{模型体积} & \textbf{延迟} & \textbf{加速比} & \textbf{精度损失} \\
\midrule
FP32 基线 & 58.03\% & 60.09\% & 609.7 MB & 7.68 ms & 1.0$\times$ & - \\
BF16 & 58.01\% & 60.18\% & 304.9 MB & 2.01 ms & \textbf{3.8$\times$} & \textbf{0.02pp} \\
FP16 & 57.96\% & 60.15\% & 304.9 MB & 2.10 ms & 3.7$\times$ & 0.07pp \\
INT8 动态(冻结层) & 42.91\% & 42.13\% & 258.4 MB & 68.3 ms & 0.11$\times$ & -15.12pp \\
ViT 剪枝1层 & $\sim$0\% & $\sim$0\% & 582.7 MB & 7.38 ms & 1.04$\times$ & 灾难性 \\
\bottomrule
\end{tabular}
\end{table}

\subsection{结果分析}

\textbf{BF16 半精度推理是最优方案}：在 RTX 4090（Ada Lovelace 架构）上，BF16 具有原生硬件支持，精度范围优于 FP16（避免 $\exp(t)$ 溢出风险）。BF16 实现：

\begin{itemize}[nosep]
    \item \textbf{3.8$\times$ 加速}：延迟从 7.68 ms/sample 降至 2.01 ms/sample；
    \item \textbf{50\% 模型体积缩减}：609.7 MB → 304.9 MB；
    \item \textbf{几乎无损精度}：t2i\_R@1 仅下降 0.02pp（58.03\% → 58.01\%），i2t\_R@1 甚至略有提升。
\end{itemize}

\textbf{层剪枝在无重训练条件下不可行}：预训练 ViT 的 12 层 encoder 形成顺序处理流水线——每层权重是在假定前序层已处理的条件下学习的。删除任何底层层导致后续层接收到未经预期的原始 embedding，产生灾难性精度崩溃（R@1 从 58\% 降至 $\sim$0\%）。这表明对预训练 Transformer，结构化剪枝必须伴随重训练或知识蒸馏才能生效。

\textbf{INT8 动态量化精度损失严重}：冻结层量化后 t2i\_R@1 从 58.03\% 降至 42.91\%（-15.12pp），全量化更降至 36.48\%。此外，\texttt{quantize\_dynamic} 的 INT8 Linear 层仅在 CPU 上有效，GPU 上反而更慢（68 ms vs 基线 7.7 ms）。

\section{结论与改进方向}
%=======================================================================

\subsection{主要结论}

\begin{enumerate}[nosep]
    \item Cosine Warmup 学习率调度是从头训练最关键的优化，单独带来 8.57\% 的 t2i\_R@1 提升；
    \item ResNet width=48 + mild ColorJitter 是从头训练模型容量与泛化的最优平衡；
    \item Flickr8k 数据集对增强策略极度敏感——RandomResizedCrop、RandAugment、TrivialAugment 均严重损害性能；
    \item 更大模型容量（width=64、4L+8H+d512、MLP 投影头）在小数据集上从头训练反而导致过拟合；
    \item 预训练视觉编码器是突破性能天花板的关键——Exp19 冻结 SigLIP ViT-B/16 后 t2i\_R@1 从 36.65\% 跃升至 47.36\%；
    \item 双预训练模型 + 部分解冻策略进一步提升——Exp21 在 ViT 和 DistilBERT 两端均只解冻顶层，可训练参数仅 36M，取得 t2i\_R@1=58.03\%、i2t\_R@1=60.09\%；
    \item 部分解冻防止过拟合——Exp20 全解冻 DistilBERT（66M 可训练）导致过拟合，Exp21 只解冻顶层 2 层（14M 可训练）后训练更健康；
    \item BF16 半精度推理是最有效的推理优化手段——3.8$\times$ 加速、50\% 体积缩减、几乎无损精度；
    \item 层剪枝在无重训练条件下不可行——预训练 Transformer 的层间依赖使直接删除底层导致灾难性精度崩溃。
\end{enumerate}

\subsection{改进方向}

\begin{enumerate}
    \item \textbf{端到端微调预训练 ViT}：Exp19 冻结了视觉编码器，Exp21 已部分解冻顶层，可进一步尝试渐进式解冻（逐层递增解冻数量）以平衡精度与过拟合。

    \item \textbf{更大规模数据集}：迁移到 Flickr30k（30000 张图）或 COCO（120000 张图），对比学习需要更多负样本对提供有效训练信号，也可尝试全解冻 DistilBERT。

    \item \textbf{知识蒸馏 + 层剪枝}：层剪枝在无重训练下不可行，但若结合知识蒸馏（用完整模型指导剪枝后模型重训练），可能实现推理加速且保持精度。

    \item \textbf{Hard Negative Mining}：在训练中主动挖掘模型容易混淆的负样本对（如同类语义图像），提供更有针对性的训练信号，提升实例级区分能力。

    \item \textbf{GPU 专用量化}：尝试 BitsAndBytes INT8 量化（HuggingFace 推荐方案）或 torch.compile()，可能提供超越 FP16/BF16 的进一步加速。
\end{enumerate}

\subsection*{A.1 SigLIP 损失函数}

\begin{lstlisting}[language=Python]
class SigLIPLoss(nn.Module):
    def __init__(self, init_logit_scale=10.0, init_logit_bias=-10.0):
        super().__init__()
        self.logit_scale = nn.Parameter(torch.log(torch.tensor(init_logit_scale)))
        self.logit_bias = nn.Parameter(torch.tensor(init_logit_bias))

    def forward(self, image_embeds, text_embeds):
        image_embeds = F.normalize(image_embeds, dim=-1)
        text_embeds  = F.normalize(text_embeds, dim=-1)
        logits = image_embeds @ text_embeds.T
        t = self.logit_scale.exp()
        b = self.logit_bias
        logits = t * logits + b
        B = logits.size(0)
        labels = 2 * torch.eye(B, device=logits.device) - 1
        loss = -labels * logits
        loss = F.softplus(loss)
        return loss.sum() / B
\end{lstlisting}
